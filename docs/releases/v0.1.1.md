# OpenRig 0.1.1 — local fork line

> Local-line release note. This is not upstream OpenRig 0.1.1. It is the first backport cut on the
> local line and applies five upstream commits recorded as `taken_commit` in `/UPSTREAM-BASE`.

## Summary

0.1.1 takes the first batch of r17's "direct suitable" upstream backports: a Vault example that no
longer listens on every interface, an empty `OPENRIG_HOME` treated as unset, bundle harness login
files refused unless explicitly included, atomic inbox-to-queue promotion, and queue work preserved
while a seat is removed. The tree carries no schema migration, no new configuration key and no
package-name change.

## Included In This Release

- A2 `d0710f6b` (`#1845`): the secrets-manager example binds Vault to `127.0.0.1:8200` instead of
  all host interfaces.
- A6 `49b12a0c` (`#1470`): the terminal-token lookup, crash-cart home lookup and TUI socket path
  treat an empty `OPENRIG_HOME` as unset, matching the rest of the CLI.
- A5 `61b4d1a8` (`#1488`): bundle creation refuses `.claude/.credentials.json`,
  `.codex/auth.json` and `.pi/agent/auth.json` by default. `rig bundle create
  --include-login-files` records the exact included paths in the manifest, and consumers show a
  credential-bearing notice.
- D5 `0d31ee1d` (`#1451`): inbox entries are promoted into queue work in one transaction, and the
  handler refuses mixed database handles.
- X1 `3f148731` (`#1459`): seat removal stops the session first and then reroutes or retains queue
  work that arrived while it was stopping.
- Version line `0.1.0 → 0.1.1` for root `openrig`, `@openrig/cli`, `@openrig/daemon`,
  `@openrig/ui` and the private `@openrig/tui`. `UPSTREAM-BASE` now lists the five taken commits.

## User-Facing Changes

- `rig --version` and the package versions read `0.1.1`.
- The bundled secrets-manager example is reachable only from the local host.
- A bundle containing a harness login file fails to create with a message naming the file and the
  remedy. Passing `--include-login-files` creates it and prints that anyone with the bundle can read
  the login; the manifest records the exact paths.
- An empty `OPENRIG_HOME` no longer produces a cwd-relative `.openrig` path.
- Seat removal reports `sessionsKilled` and, when it kept the node for late work, `retained` /
  `sessionStopped`.

## Operator / Setup Notes

- Restart the daemon after upgrading (`rig daemon stop`, then `rig daemon start`), as with any local
  build that changes daemon source.
- No migration runs; the newest remains 114.
- The `--include-login-files` flag is per create. Treat a bundle that contains login files as
  credential-bearing even when it is intentional.
- This is a local cut: no npm publish, no git tag and no GitHub release. Publishing identity remains
  an owner decision.

## Known Limitations

- Only the first of r17's suitable batches is included. `B1/B2/B4/D1`, `C5/D4/X2`, `A4` and the
  manual `A1/C4/C6/X3` ports are later work; `A3/C1/C2/D2/D3/X4` need subsystems this tree lacks.
- `unpack()` now returns login-file warnings, but the pod/legacy bundle source resolvers and
  `bundle-content-routing.ts` do not print them; the create, inspect, install and bootstrap routes
  do. This matches the upstream commit's consumer surface and is recorded as a follow-up.
- The existing story-graph UI tests assert English month names, so the full suite must run under an
  English locale (`LC_ALL=en_US.UTF-8`) on a host whose default locale is `zh_CN`.
- The release is local only: no npm publication, no git tag, no GitHub release.
