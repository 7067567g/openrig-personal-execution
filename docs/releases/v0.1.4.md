# openrig-local 0.1.4 — dependency security floors

> Local-line release note. This is not upstream OpenRig 0.1.4 and is not related to upstream
> versions. It is a security-maintenance cut of the personal local fork described in
> `/docs/reference/fork-and-upstream.md`; lineage and policy live in `/UPSTREAM-BASE`.

## Summary

0.1.4 raises the two dependencies that sit on OpenRig's own reachable runtime paths — `tar`
for `.rigbundle` pack/unpack and `hono` for the daemon HTTP router — past their October-2026
advisories, applies the semver-compatible remainder of `npm audit`, and adds a floor test so a
later install cannot silently bring the old versions back. It also adds a shipped
`docs/reference/security-notes.md` for the two host-level exposures this repository cannot fix:
the Ubuntu kernel waiting on `7.0.0-43.43`, and PyTorch `.ckpt`/`.pth` loading. No schema,
configuration key, command name or default behavior changes.

## Included In This Release

- **`tar` 7.5.13 → 7.5.22** (`> 7.5.20`). `packages/daemon/src/domain/bundle-archive.ts`
  parses `.rigbundle` archives when packing (`:37`) and unpacking (`:128`). The digest check,
  path pre-scan and extraction filter prevent path traversal, but not the parser-level
  crash/DoS covered by the six `<= 7.5.20` advisories.
- **`hono` 4.12.8 → 4.13.13** (`>= 4.13.11`). The daemon router
  (`packages/daemon/src/server.ts:5`) and the terminal WebSocket adapter
  (`@hono/node-server`, used at `:763`) are directly reachable.
- **The semver-compatible remainder:** `@hono/node-server` 1.19.17,
  `@modelcontextprotocol/sdk` 1.32.2, `zod` 4.6.7, `smol-toml` 1.9.1, `ws` 8.22.0,
  `fast-uri` 3.1.9, `postcss` 8.5.31, `vite` 6.4.5, `vitest` 3.2.7, and the transitive
  `qs`/`body-parser`/`seroval`/`proxy-addr`/`ip-address`/`picomatch`/`nanoid`/
  `source-map-js`/`browserslist`/`@babel/*` updates. Every one stays inside its existing major.
- **`scripts/check-dependency-floors.test.mjs`** — a repo-level test that reads the lockfile
  and the workspace manifests and fails when a guarded package resolves below its fixed
  version, when a manifest re-admits an old range, or when `tar`/`hono`/`@hono/node-server`
  stop being runtime dependencies of the CLI/daemon.
- **`docs/reference/security-notes.md`** — a shipped operator note covering the kernel
  (CVE-2026-99999/PwnEscape, wait for Ubuntu `7.0.0-43.43`, no untrusted KVM guests before
  it), PyTorch (CVE-2026-24747, do not load untrusted `.ckpt`/`.pth`/`.pt`, move to torch
  ≥ 2.10.0), and the npm floor above.
- Local version line `0.1.3 → 0.1.4` for the root, four workspaces, lockfile and
  `UPSTREAM-BASE.local_line`. No `taken_commit` is appended by this cut.

## User-Facing Changes

- Importing a `.rigbundle` now uses a tar parser that is past the October-2026 file-smuggling,
  PAX type-confusion and decompression-DoS advisories. The bundle trust model is unchanged:
  integrity checks detect corruption/tampering, not authorship; only import bundles from
  sources you trust.
- The daemon's HTTP stack is on the fixed Hono release. Route shapes, headers, authentication
  and status codes are unchanged.
- `npm audit` on a fresh install of this tree reports **6 findings (2 critical, 0 high,
  4 moderate)** instead of 27 (5 critical, 13 high). The two critical and four moderate
  remaining findings are dev-only (`vitest`/`tinypool`/`@vitest/mocker`) or Tailwind 3
  build-time (`tailwindcss`/`postcss-nested`/`postcss-selector-parser`); none is in a
  daemon or CLI runtime path.
- The new security page is available through `rig context get reference/security-notes.md`
  (and under `$OPENRIG_HOME/reference/security-notes.md`).
- Command names, `OPENRIG_HOME`, `~/.openrig`, wire fields, runtime ids, plugin ids,
  configuration keys and the database schema (newest 114) are unchanged.

## Operator / Setup Notes

- No database migration runs; the newest schema remains 114. Restart the daemon the usual
  way (`rig daemon stop`, then `rig daemon start`) so `/healthz` and the version route report
  `0.1.4`.
- No new switch to turn on. Everything in this cut is a dependency floor or documentation.
- **Kernel action is the operator's:** when Ubuntu publishes `7.0.0-43.43` (or later), run
  `sudo apt update && sudo apt full-upgrade` and reboot. Do not run untrusted KVM guests on
  the current kernel. This release cannot perform the OS upgrade.
- **Torch action is the operator's:** the ComfyUI virtualenv is outside this repository.
  Do not load `.ckpt`/`.pth`/`.pt` files from untrusted sources; when the environment is
  rebuilt, install torch ≥ 2.10.0.
- No npm publish, git tag or GitHub release is made by this cut. Publishing identity remains
  an owner decision.

## Known Limitations

- The remaining `vitest`/`tinypool` critical advisory is not fixed. It is a test-runner
  worker-pool issue, and the fix is vitest 5, a test-infrastructure major migration. It is a
  devDependency and is not in the published tarball.
- `tailwindcss` 3.4.19 is the newest 3.x and remains in the moderate `postcss-selector-parser`
  advisory range. Fixing it requires Tailwind 4, an intentional UI-toolchain migration.
- `npm audit fix` changed 83 lockfile entries in total (2 added, 0 removed). The full table is
  in `runs/openrig-r23-deps/reports/data-lock-version-changes.txt`; the package-level and full
  suites are the regression evidence.
- The Vite upgrade (6.4.1 → 6.4.5, GHSA-rq7h-c2jc-7f22) tightens `server.fs.allow` in the
  Vitest module runner. Two tests that dynamically imported a fixture from `os.tmpdir()` now
  create it under `packages/*/test/.tmp-*`. Assertions and production paths are unchanged.
- The kernel and PyTorch items are host facts as of 2026-10-25. `security-notes.md` is a
  point-in-time note, not a live scanner; re-check the versions before relying on it.
