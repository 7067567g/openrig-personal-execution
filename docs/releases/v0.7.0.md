# OpenRig v0.7.0 — seat-load isolation and resource budgets (P0 + P1)

OpenRig 0.7.0 is the first release prepared around the
[seat-load isolation and resource budgets plan](../reference/seat-load-isolation-and-resource-budgets-plan.md):
it lands the P0 DSH foundation and the P1 host-protection controls. Every new
control is opt-in; apart from the workflow closure-evidence check noted below, an
existing rig runs exactly as it did on 0.6.11.

Publication status and date are recorded on the GitHub release and npm once this
candidate is published. This note describes source preparation, not a published
artifact.

## Summary

A shared DSH Web process and an unbounded batch of seats are the two ways a busy
rig can make the whole host unusable. 0.7.0 makes the DSH shim a versioned part
of the repository, pins the `session`/`status`/`final` protocol it speaks, and
adds four default-off controls — seat launch admission, per-turn task budgets,
toolchain concurrency projection and provider/model seat-start limiting — plus a
per-seat enforcement view in `rig ps --resources`. It does not add cgroup CPU or
memory limits. One deliberate tightening is not a new control: a workflow closure
that declares an evidence file is now verified instead of silently accepted.

## Included In This Release

- P0: the shared-web DSH shim is vendored under `packages/daemon/assets/dsh/`
  with a README and contract tests for `session` / `status` / `final`, error
  without final, non-zero exit, exit 0 without final, duplicate sessions and
  malformed lines.
- P0: [DSH execution paths](../reference/dsh-execution-paths.md) documents the
  shared-web against headless trade-off.
- P1: default-off seat launch admission with global/per-rig caps, FIFO queueing,
  reserved interactive slots and `admission_timeout` without a start.
- P1: default-off per-turn task budgets (`max_wall_time`, `max_steps`,
  `max_tool_calls`, `max_tokens`, `max_retries`), enforced in the pane-hosted
  runner and reported in its sidecar.
- P1: default-off toolchain concurrency projection into the seat's tmux
  environment (seven variables, existing values win).
- P1: default-off provider/model live-seat semaphore and seat-start token
  bucket.
- P1: `rig ps --resources` reports `scope`, `limit`, `current`, `peak`,
  `enforced_by`, `backend` and a reason per seat and resource.
- Transcript capture's default cadence (2 s active, 1000 lines) and the lowered
  path (10 s, 200 lines) are pinned by tests.
- Workflow closure evidence: a `handoff`/`done` projection that declares
  `closureEvidence.evidence_ref` now requires an existing regular file (absolute,
  or relative to the workflow spec's directory). An optional
  `closureEvidence.evidence_digest` is checked as a sha256. A missing, unreadable
  or changed artifact is refused with a zero-write HTTP 400
  (`evidence_ref_missing`, `evidence_ref_not_file`, `evidence_ref_unreadable`,
  `evidence_digest_mismatch`, …) instead of advancing the packet.

## User-Facing Changes

- `rig ps --resources` has a new per-seat table and a `seats[]` array in
  `--json`. It shows `not_enforced` with a reason wherever a control is off, a
  budget dimension was never reported by the runtime, or the platform has no
  backend. `cpu`/`memory` read `cgroup_budget_not_implemented` on Linux and
  `platform_unsupported` elsewhere.
- `rig config` lists the new `resources.*` and `budget.*` keys. All master
  switches default to `false`.
- A pre-0.7.0 daemon returns no `seats[]`; the CLI prints that the daemon does
  not report per-seat enforcement instead of inventing rows.
- A workflow `handoff`/`done` that names a nonexistent or changed evidence file
  now fails with HTTP 400 instead of advancing. This is the release's one
  deliberate behavioral tightening; closures that declare no `evidence_ref` are
  unchanged.
- No other existing command output changes when the switches stay off.

## Operator / Setup Notes

- Restart the daemon after upgrading the CLI. There are no database migrations
  in 0.7.0.
- Turn on only what the host needs. Suggested first step:
  `rig config set resources.admission.enabled true` with
  `resources.admission.max_concurrent` and `resources.admission.max_per_rig`;
  then, if provider starts are the bottleneck,
  `resources.provider_limit.enabled true` with
  `resources.provider_limit.max_active_seats`.
- Task budgets are read at seat launch time: a flip applies to the next launch,
  not to an already-running runner.
- Toolchain projection is read at launch and only reaches the seat's tmux
  session environment; it does not change the daemon's environment or rig YAML.
- Stop the daemon before changing `transcripts.enabled` or `transcripts.path`;
  the other transcript settings still reload at runtime.
- No command, database schema, config default or default launch path breaks.
  The one deliberate behavioral tightening applies only to workflow closures
  that declare an `evidence_ref`; see above.

## Known Limitations

- No cgroup/systemd seat scopes and no CPU/memory sampling. `rig ps --resources`
  says so explicitly; the design remains P3.
- Provider limiting gates seat starts, not individual provider API calls. The
  daemon does not proxy provider traffic.
- Admission and provider wait queues are in memory: a daemon restart drops
  waiters rather than resurrecting stale launches.
- `provider_rate_limited` and `admission_timeout` still surface through the
  existing session-create error path (HTTP 500). A dedicated 429/503 mapping is
  not part of this release.
- The shared-web DSH shim emits no step, tool-call or token events, so those
  budget dimensions stay `not_reported` on that path. Only wall time is
  enforceable there.
- Per-rig `resources:` YAML is not implemented; the config surface is
  `rig config`.

## Verification Performed

- Targeted daemon tests: launch admission, task budget, toolchain env,
  provider limiter, DSH protocol/shim, and the new resource projection.
- Targeted CLI tests: `rig ps --resources` human output, `--json`, remote host
  classification and the older-daemon fallback.
- `npm run lint` (daemon/UI/CLI/TUI typecheck) passes.
- `npm run test:repo` (repository scripts, docs guard, context-pack check)
  passes.
- The release gate (`npm run gate`) is green on the final release tree: `npm run
  lint` passes, and `npm run test` passes with no failures (`test:repo` 315 pass /
  1 skip; daemon 17 641; CLI 4 886; TUI 1 008). The receipt names the candidate
  commit; it is archived with the release preparation evidence.
- Earlier runs of the daemon and CLI suites had environment-dependent failures
  (tmux 3.6 pane/transport behavior, timing-sensitive reads, a non-ASCII checkout
  path). Two environment-sensitive test files were repaired during release
  verification — tmux's full set of "server is gone" messages, and a
  barrier-timeout test that had raced a 0 ms budget — with product code unchanged.
- No real 4-seat fleet or port 3080 was exercised; the hard boundary for this
  work forbids restarting or occupying the owner's service.
