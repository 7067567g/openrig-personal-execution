# OpenRig 0.6.7 — the first hour

> Backfilled release note, written 2026-10-24 from the `0.6.7` section of
> [`CHANGELOG.md`](../../CHANGELOG.md). It adds no new test run; the release's
> original verification record is on the
> [GitHub release](https://github.com/mvschwarz/openrig/releases/tag/v0.6.7).

0.6.7 is about the first hour: after install or start, the agent opens the OpenRig
TUI and the kernel's operator for you, laid out for your terminal, and the operator
asks fewer permission questions.

## Before you upgrade

- Restart the daemon after upgrading the CLI. The first start runs two migrations
  (the team install folder and the Slack thread-part map) and installs openrig-core
  0.1.8, which running seats pick up at their next launch.
- `rig setup` now installs herdr by default on macOS and Linux with herdr's own
  installer (`--no-herdr` declines; a failed install falls back to plain tmux),
  offers Ghostty on a Mac, and stops installing or configuring cmux. `rig setup
  --json` drops `cmux_install` and adds `herdr_install` / `ghostty_install`.
- `rig terminal open <view>` opens a desktop window by default; `--provider
  herdr|cmux` adds tiles to an open workspace instead. The default `saved:kernel`
  view is laid out by terminal width, and a saved `kernel` view still wins.
- `rig doctor` adds four rows that check Claude Code and Codex installs and a login
  or configured provider credential, and exits 1 when either is missing or has
  neither, including an unused harness.
- The `rigs` and `refocusing` skills are copied into `~/.claude/skills` and
  `~/.agents/skills` and refreshed on upgrade, leaving a `skills.sh` copy of `rigs`
  alone.
- Claude team seats run lifecycle `--help` and common spellings of allowed commands
  without a prompt; lifecycle actions still ask. A Claude seat's status-line command
  is rewritten with quoted paths and its activity relay moves under
  `$OPENRIG_HOME/state/claude-activity-hooks/` at its next launch.

## Highlights

- **Open the TUI and operator as the step after install or start** with
  `rig terminal open saved:kernel --window`: the operator leads under 120 columns,
  the dashboard and operator share the first tab from 120, and the advisor gets its
  own tab. It reuses an open herdr view, never resizes existing windows, and prints
  the command to run when there is no display.
- **Carry the install-to-operator route in the `rigs` skill**: finish the install,
  hand over the goal, folder and branch, relay the operator's questions, and give a
  command when no window opens.
- **Publish a one-command install** with a stable link and a `--dry-run` preview.
- **Refuse a send or wake to a Claude seat** whose unrecognized screen follows a
  hook saying it is waiting for a person, and escalate the wake. A seat waiting at
  an approval stays counted as needing attention after a daemon restart.
- **Add `rig slack channel-map list|set|remove`** for a channel per rig or seat,
  checked by `rig slack verify` and shown in the TUI. Emoji reactions on ask
  messages, long asks as numbered thread replies, "Also send to #channel" replies,
  and retrying a socket that fails or stalls while opening are covered.
- **Ship `rig context get reference/whats-new.md`**, the what-changed note for
  agents, read by the `openrig-upgrade` skill's last step.
- **Let `rig seat handover` run again on the same seat**, and teach seats to write
  their recap with `rig context recap-write` before a handover.
- **Publish the built-in starter and factory leads' rosters** at first start and
  show each first-team choice's graph in the shared TUI.
