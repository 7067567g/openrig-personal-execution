# OpenRig 0.6.10 — setup choices, resume proof, delivery and attach

> Backfilled release note, written 2026-10-24 from the `0.6.10` section of
> [`CHANGELOG.md`](../../CHANGELOG.md). It adds no new test run; the release's
> original verification record is on the
> [GitHub release](https://github.com/mvschwarz/openrig/releases/tag/v0.6.10).

0.6.10 is a fix release, most of it from the community. Setup can be told which
agent harnesses a person uses, a resumed Claude seat whose session ID changed can
prove and restore, sends reach Codex seats behind a launcher and Claude seats
showing a suggested prompt, restore puts back the guidance `rig down` removed, and
attach commands name the tmux server the daemon actually uses.

## Before you upgrade

- Restart the daemon after upgrading the CLI. Migration `099` adds
  `idx_queue_items_recovery_tags`; migration `101` adds four empty `sessions`
  columns for a resumed Claude conversation's new ID. Neither changes existing data.
  There is no migration `100`. openrig-core moves from 0.1.8 to 0.1.9.
- `rig capture --lines N` now means the last N lines, with stderr saying how many
  earlier lines were cut. `--history-plus-pane` keeps the old behavior.
- Compact `rig queue list`, `overdue` and `undelivered` rows carry `summary` and
  leave elided fields out entirely; `fieldsElided` names them.
- `rig launch <rigId> <seat>` on a seat whose agent exited to a shell returns
  `attention_required` and exit 1, naming the ways back.
- `rig up <rig> --existing` reports `partially_restored` and exits 1 when a seat is
  still missing part of its OpenRig guidance; the node lists `guidanceGaps`.
- `lastNudgeResult` reads `claimed` on a claimed row whose wake was not confirmed;
  the recorded wire value is in `lastNudgeWireResult`.
- `rig chatroom history` without `--after` or `--since` returns the newest messages,
  still oldest first.

## Highlights

- **Choose harnesses at setup**: `rig setup --providers claude`, `codex`, `both` or
  a comma list. A harness not chosen is not installed or checked and reads
  `skipped`, never failed.
- **Prove a resumed Claude seat under a new session ID** when its first
  `SessionStart` hook from the launched process reports `source: "resume"`. It
  restores as `resumed` and sends without the "launch identity differs" warning.
- **Reach a Codex seat behind a launcher** that starts Codex as a child; the deepest
  `codex` on one process chain counts as the seat.
- **Treat Claude's faint suggested prompt as empty**, not as a person's draft, so a
  send to that idle seat is not refused as `prompt_draft`. Typed text is still
  refused.
- **Put back the OpenRig guidance blocks** `rig down` removed from `CLAUDE.md`,
  `CLAUDE.local.md` or `AGENTS.md` before a resumed seat starts, without touching
  the person's own text.
- **Name the daemon's tmux server in printed attach commands** (`-L` or `-S`) when
  it runs on a non-default socket.
- **Report a seat's wake result and claim** from `rig queue create --verify` as soon
  as one is recorded, instead of `still-pending` after 30 seconds.
- **Start the daemon after a timed-out health probe** when the port is free, as on
  WSL2; refuse only when the port is really held.

## Limits stated at the time

The changelog section records no separate "Known limitations" block for this
release. Its caveats are in the item text above (for example, the provider check
tells setup what is installed, not what a provider will do at run time). The
original GitHub release carries the verification and issue list.
