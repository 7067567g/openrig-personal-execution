# OpenRig 0.6.9 — first hour and Slack delivery

> Backfilled release note, written 2026-10-24 from the `0.6.9` section of
> [`CHANGELOG.md`](../../CHANGELOG.md). It adds no new test run; the release's
> original verification record is on the
> [GitHub release](https://github.com/mvschwarz/openrig/releases/tag/v0.6.9).

0.6.9 is a quick fix release for what people meet in their first hour and in the
Slack channel: a Slack connection that stops delivering is caught and replaced, a
typed Slack answer is kept, Slack status shows what waits to be retried, a kernel
that recovered reads ready, and a cross-host send or a long chatroom wait no longer
reports failure when the work went through.

## Before you upgrade

- Restart the daemon after upgrading the CLI. Migration `098` adds an index on
  `(qitem_id, transition_id)` to the queue's transition history. openrig-core stays
  at 0.1.8.
- `rig scope <tier> approve --workspace <path>` stamps the named work tree and
  refuses a named workspace with no `missions/` folder instead of stamping the
  configured one.
- A cross-host `rig send --host` to an HTTP-registered host gets a 30-second request
  budget plus any `--wait-for-idle` time. A send that may have arrived is reported
  as `remote-outcome-unknown` ("Delivery UNCONFIRMED", exit 1), with the check to run
  before any resend. Only a host never reached reads as unreachable.

## Highlights

- **Keep a typed Slack reply to a decision** with structured questions in
  `humanAnswers`, under the first unanswered question. Text that matches an option
  ID is never read as a click, and closing is still not approval.
- **Show retained inbound retry records** in `rig slack status` — messages,
  reactions and click answers — or say the count is unknown and why.
- **Drop a retained Slack alert replayed at gateway start** when its row has left
  the active states, recording why on the row. Open rows' alerts, decision-resolved
  notices and digests still post.
- **Detect a Slack Socket Mode connection that stays open while events stop**, by
  server pings and by the echo of OpenRig's own posts, and replace it. The new
  connection opens first, at most once every 5 minutes, and `rig slack status` names
  the delivery state beside "connected".
- **Report a kernel ready once every declared seat recovered** from a failed start,
  with the earlier failure on its own line and as `last_boot_failure` from
  `/api/kernel/status`.
- **Keep a long `rig chatroom wait` going** through a slow or restarting daemon
  until its `--timeout`.

## Other changes

- A Nix-wrapped Claude Code is recognized as the seat runtime, so its seats read
  `running`.
- The refocus work packet is added **off by default**; nothing changes unless it is
  enabled.
