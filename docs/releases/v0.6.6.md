# OpenRig 0.6.6 — from install to a launched team

> Backfilled release note, written 2026-10-24 from the `0.6.6` section of
> [`CHANGELOG.md`](../../CHANGELOG.md). It adds no new test run; the release says
> its "how it was tested and known issues" record lives on the
> [GitHub release](https://github.com/mvschwarz/openrig/releases/tag/v0.6.6).

0.6.6 is about getting to your agents fast: after install, the kernel's operator
asks what you want to build, offers three teams and launches one, and teams can be
shared and installed from a GitHub folder link. It was built from main at
`2620dea8` after #900; work merged later is not included.

## Before you upgrade

- Restart the daemon after upgrading the CLI. The first start adds the saved
  non-interruptive choice to rigs and installs openrig-core 0.1.4, which running
  seats pick up at their next launch.
- The built-in teams are renamed: `starter` (a Claude Code builder and a Codex
  reviewer; `first-project` is an alias), `factory`, `code-review` (was
  `adversarial-review`), `research` (was `research-team`) and `pm` (was `pm-team`),
  with no alias for the last three. `conveyor`, `demo`, `implementation-pair`,
  `product-team`, `first-project-claude`, `first-project-mixed` and `factory-rsi`
  leave the shelf. Existing rigs created from removed specs keep restoring.
- Claude Code and Codex seats outside the kernel with no explicit policy, saved seat
  choice or named Codex profile get a team default at their next launch. Set an
  explicit policy such as `permission_policy: none` to keep the old behavior.
- Seats of a rig named `kernel` get an operational default unless they have an
  explicit choice: Claude Code in `acceptEdits` with a file/read/operational allow
  list; Codex with `-s danger-full-access -a never`.
- A new rig's Docker Compose project is derived from its rig ID, not its name;
  existing rigs keep theirs. A failed boot brings a newly started project down
  (never with volumes), conflicting replaced generations are refused with
  `compose_project_conflict`, and `rig down` exits 2 when it keeps a project a live
  same-name rig still uses.
- A launch-created `AGENTS.md` or `CLAUDE.md` stays visible to Git with a warning
  naming the exclude line; new files under `.codex/plugins/openrig-core/` are
  excluded in a marked `info/exclude` block.
- Managed compaction restore maps are written in the seat's launch folder under
  `.openrig/compaction/`, git-ignored, with the OpenRig home as fallback.

## Highlights

- **The kernel operator greets first**, asks the goal once, offers starter,
  workshop and factory with one recommendation and a drawing, adapts the team to the
  providers present, launches on a yes, shows the team and hands the goal to the
  lead. An installing agent keeps the kernel and passes the goal to the operator.
- **Open a terminal space with the kernel's TUI, advisor and operator** after
  install, with a default `saved:kernel` view for every kernel runtime mix, and exact
  tmux or `ssh -t` attach commands when herdr or cmux is unavailable.
- **Accept public GitHub folder links** in `rig up` and `rig bundle create`,
  `inspect` and `install`, pinned to one commit. Declare configurations with
  `rig bundle configurations`, `--preset` and `--seat`; preview what a bundle will do
  before install; check it with `rig bundle check`; and install `.rigbundle` files
  through `rig bootstrap`.
- **Save `--non-interruptive` on the rig** for full-bypass seats, clear it with
  `--no-non-interruptive`, default it with `launch.non_interruptive`, and accept
  `non_interruptive:` in a rig spec.
- **Copy a selected plugin's skills** into Claude Code and Codex seats' skill
  folders.
- **Add `rig roster list`, `show` and `find`**, and `rig telemetry events`,
  `transitions` and `tenures`.
- **Pick the `rig context work-install` project** by rig, then working folder, then
  the only unclaimed project, with candidate commands when still ambiguous.
- **Type `rig send --dangerously-interact` answers as keystrokes**, so numbered menus
  get the digit.
