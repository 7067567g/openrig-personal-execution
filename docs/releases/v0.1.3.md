# openrig-local 0.1.3 — second backport batch

> Local-line release note. This is not upstream OpenRig 0.1.3 and is not related to upstream
> versions. It is the second backport cut of the personal local fork described in
> `/docs/reference/fork-and-upstream.md`; lineage and policy live in `/UPSTREAM-BASE`.

## Summary

0.1.3 applies four adapted upstream fixes from the 0.7.0-era data-integrity and recovery
batches: a single transport send now marks its outbox audit row delivered, the CLI
host-bindings lock waits out a slow holder instead of overwriting it, a managed
plugin/global-skill refresh preserves the differing files it replaces, and one failed
stuck-sweep finding no longer aborts the rest of the pass. No schema migration, no new
configuration key, no command rename, and no default change outside those failure paths.

## Included In This Release

- **B1** (`#1844`) — `POST /api/transport/send` marks its sender-side outbox audit row
  `delivered` after a landed send, matching broadcast's per-recipient rows. The row
  previously stayed `pending` for ever. Audit-only: delivery is unchanged.
- **B2** (`#1862`) — the CLI host-bindings advisory lock sleeps between retries
  (`Atomics.wait`) and waits past the 2 s stale threshold before failing open. A holder
  that stalls for 600 ms is waited out rather than overwritten; a genuinely stale lock is
  still taken over.
- **B4** (`#1821`) — before a managed plugin or marked global-skill refresh replaces a
  differing file, it copies that file to
  `$OPENRIG_HOME/backups/managed-refresh/<uuid>/` and logs the recovery path. If the copy
  fails, the refresh is skipped and the existing files stay. The generated
  `scripts/skill-edge-digests.generated.json` was regenerated from disk, not hand-edited.
- **D1** (`#1903`) — a stuck-sweep finding whose creation fails (for example a destination
  rig that no longer resolves) is logged and reported instead of aborting the pass. The
  findings that were made are kept and the pass still records `failed` with the row named.
- Local version line `0.1.2 → 0.1.3` for root, CLI, daemon, UI, the private TUI, the
  lockfile and `UPSTREAM-BASE.local_line`; four `taken_commit` entries appended
  (append-only) with subjects and upstream PR numbers.

## User-Facing Changes

- A `rig send` (single, derived actor) now leaves a `delivered` audit row with a
  `delivered_at` stamp instead of a permanently pending one.
- Concurrent `send` / `capture` / `doctor` on a loaded host are less likely to lose a
  host-binding conflict record: a writer waits up to the stale threshold instead of
  failing open after ~200 ms.
- An upgrade/refresh that replaces an edited managed plugin or marked global skill keeps a
  byte-for-byte recovery copy under `$OPENRIG_HOME/backups/managed-refresh/`. The copy does
  not keep the custom behavior active after the refresh.
- A stuck-sweep pass with one unroutable finding keeps its other findings and reports
  `failed` (with the failed row named) rather than losing the whole pass.
- Command names, `OPENRIG_HOME`, `~/.openrig`, wire fields, runtime ids, plugin ids,
  configuration keys and the database schema (newest 114) are unchanged.

## Operator / Setup Notes

- No database migration runs; the newest remains 114.
- The `managed-refresh` backup directory is new write output under `OPENRIG_HOME`. It is
  not scanned as a managed plugin directory. Old copies are not pruned by this cut.
- No npm publish, git tag or GitHub release is made by this cut. Publishing identity remains
  an owner decision.
- `scripts/check-upstream-base.test.mjs` was updated for the 0.1.3 line and the nine
  recorded `taken_commit` entries; the validator itself is unchanged.

## Known Limitations

- B2's lock still has the named stale-takeover tail documented in the source (the original
  holder's release can remove the new holder's lock). It is unchanged by this backport.
- B4 preserves bytes, not behavior: after a refresh the preserved copy must be reapplied
  deliberately by the operator.
- D1 leaves a failed finding's underlying row `detected`; the next pass retries it.
- Upstream inventory remains a manual, on-demand activity.
- The daemon/UI story-graph tests assert English month names, so the full suite is run with
  `LC_ALL=en_US.UTF-8` on hosts whose default locale is not English. This cut does not fix
  that unrelated locale debt.
- `test/seat-activity-retirement.test.ts` has a pre-existing tmux timing flake after
  `kill-session` removes the last session (the immediate `new-session` can see the dying
  server and report "server exited unexpectedly"). It reproduces without this cut's changes
  and is unrelated to the four backports; see the round report's flake evidence.
