# OpenRig 0.1.0 — local fork line

> Local-line release note. This is **not** upstream OpenRig 0.1.0, and it has nothing to do with the
> archive's upstream `v0.1.12.md`. 0.1.0 starts the local fork line from the 0.7.0 pre-line tree; the
> upstream commits this fork is based on are recorded in `/UPSTREAM-BASE`.

## Summary

0.1.0 cuts the local line's first version. It carries the same tree as the 0.7.0 pre-line and changes
only the version line, the lineage record and the release documentation. No upstream commit is
applied, no feature is merged, and no command, default, migration or wire shape changes. The local
0.7.0 was never published, so there is no external upgrade path to preserve.

## Included In This Release

- Version line reset to `0.1.0` for root `openrig`, `@openrig/cli`, `@openrig/daemon` and
  `@openrig/ui`; `@openrig/tui` stays private `0.1.0`.
- `UPSTREAM-BASE` at the repository root: the upstream v0.6.11 baseline (tag and commit), the real
  fork base `eabc816e`, the upstream v0.7.0 comparison commit, the upstream snapshot commit and the
  sync date. `scripts/check-upstream-base.mjs` validates the record in `npm run test:repo`.
- `rig launch --plan` keeps working on this line: the plan guard treats a `0.1.x` daemon as
  supporting `plan: true`, because this line was cut from the tree that added plan support. The
  upstream `0.5.9` floor still applies to every other version, and a test pins the local package
  version to the declared line.
- Release documentation aligned with the new line: `CHANGELOG.md`, this note,
  `docs/releases/README.md`, `docs/reference/whats-new.md`, the reference index anchor and the
  roadmap's "shipped in 0.7.0" wording.

## User-Facing Changes

- `rig --version` and the package versions read `0.1.0` instead of `0.7.0`.
- `rig launch --plan` works against a daemon on the local `0.1.x` line again; without the guard
  exception it would refuse to send and cite the upstream `0.5.9` floor.
- Anything that compares versions must account for `0.1.0 < 0.7.0`. The local 0.7.0 was never
  published, so no external install is downgraded by this cut.

## Operator / Setup Notes

- **Do not publish this version under `@openrig/cli`.** The name `@openrig/cli@0.1.0` already exists
  on npm from an earlier upstream release; this local 0.1.0 is different code. Publishing identity
  is an owner decision and remains open; this cut does not publish, tag or push.
- Upgrade path from a pre-line 0.7.0 tarball: clean install and restart the daemon
  (`rig daemon stop`, then `rig daemon start`). There are no new migrations; the newest remains 114.
- Bundles that declare `compatibility.min_daemon_version` at `0.5.x` or later are refused on this
  line. That is the declared minimum being honoured, not a bug; the bundled rigs in this tree declare
  no minimum.

## Known Limitations

- The plan guard's local-line exception is keyed on the version prefix, not a daemon capability, so
  `--host` against a genuine upstream 0.1.x daemon would be treated as supporting `plan: true`. A
  capability in `/healthz` is the durable fix and is deferred to a later round.
- CPU and memory budgets, per-rig `resources:` YAML and isolated DSH execution remain unimplemented,
  exactly as on the 0.7.0 pre-line.
- The release is local only: no npm publication, no git tag, no GitHub release.
