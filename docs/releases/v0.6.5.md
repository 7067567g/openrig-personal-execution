# OpenRig 0.6.5 — effort, continuity and resource visibility

> Backfilled release note, written 2026-10-24 from the `0.6.5` section of
> [`CHANGELOG.md`](../../CHANGELOG.md). It adds no new test run; the release section
> points to the
> [GitHub release](https://github.com/mvschwarz/openrig/releases/tag/v0.6.5) for
> known issues.

0.6.5 collects what was merged to main since 0.6.4: per-seat reasoning effort,
Codex seats reaching the local daemon under the default sandbox, saving the current
Claude conversation before shutdown, a host-resource view, clickable Slack
questions, and the Oh My Pi runtime. It was built from main at `b345706b` plus eight
later changes.

## Before you upgrade

- If your shell rc sets a `CODEX_HOME` different from the daemon's, align them (or
  unset the daemon's explicit selection). Managed resume now uses the daemon-selected
  home and does not search the other home for an earlier thread.
- Restart the daemon after upgrading the CLI; the running daemon keeps its old build.
  The first start updates the database, including two usage-sample indexes whose
  build time on very large histories has not been measured, and installs
  openrig-core 0.1.3, picked up by running seats at their next launch.
- Codex seats on the default `workspace-write` sandbox get network access inside the
  sandbox unless your Codex config or a managed requirement says otherwise. Set
  `network_access = false` under `[sandbox_workspace_write]` to keep it off.
- The daemon's OpenRig settings and its matching `rig` are re-applied at every seat
  launch, so shell startup files cannot redirect a seat.

## Highlights

- **Set reasoning effort per seat** with `effort` on a pod member, in profile
  `preferences` or in agent `defaults`; passed to Claude as `--effort` and to Codex
  as `model_reasoning_effort`, unchecked, ignored by Pi. Claude identity proof
  recognizes `--effort`, so an effort-set seat passes the exact check.
- **Let Codex seats reach the local daemon under the default sandbox** after a short
  read of the Codex configuration (about 0.1–1.5 seconds; network stays off if it
  takes over 4 seconds). A blocked daemon connection is named as blocked.
- **Save the current Claude conversation before shutdown**, so `rig down` and
  `rig up` after `/clear` restore it. For an archived rig, refresh skips another
  rig's live namesake and the archived row keeps its own saved conversation.
- **Record the assigned session ID for fresh Claude launches** and confirm wrapped
  and natively installed Claude seats from the native process and the saved
  conversation ID during restore, readiness, identity checks and
  `rig seat clear-attention`.
- **Wait for an attempt-specific restore map before managed Claude compaction**
  sends `/compact` (up to 25 minutes for automatic compaction). Add
  `rig compact --state`, `--cancel` and `--skip-map`.
- **Add `rig ps --resources`** for host load and transcript capture cost, back idle
  capture off to once every 6 seconds, and apply transcript line and interval
  settings to running seats without a restart.
- **Add clickable Slack questions on human decisions**; older Slack apps must turn
  on Interactivity by hand. Thread follow-up updates with
  `rig queue create --human-intent update --reply-to <id>`, and upload local
  evidence files plus video and PDF up to 50 MiB.
- **Add the Oh My Pi runtime (`runtime: omp`)** with per-seat state.
- **Validate rig specs locally without a daemon**, and teach
  `rig context work-install` / `--deliver` / `--project <id>` in onboarding and the
  restore and reorientation skills.

## Limits stated at the time

- Oh My Pi had no live provider session run, and full-restore recovery of OMP seats
  was still open.
- Managed Claude compaction was not tested against a real Claude compaction.
- Slack questions and media were tested against a simulated Slack only.
- The Codex local-daemon path was not checked with real logins, managed policy
  bundles or on Linux.
- The `/clear`-then-`rig down` path was checked with a real Claude session on Linux;
  a change between that read and shutdown is unverified.
