# openrig-local 0.1.2 — package identity

> Local-line release note. This is not upstream OpenRig 0.1.2 and is not related to upstream
> versions. It is the identity cut of the personal local fork described in
> `/docs/reference/fork-and-upstream.md`; lineage and policy live in `/UPSTREAM-BASE`.

## Summary

0.1.2 gives the local line its own package identity: the root package is `openrig-local` and the
workspaces are `@openrig-local/{cli,daemon,ui,tui}`. Behavior is unchanged — no schema
migration, no new configuration key, no default change, and no command rename. `rig --version`
now names the fork, and the repository records how it relates to upstream (read-only reference,
independent version line, manual backports).

## Included In This Release

- Root package `openrig` → `openrig-local`; workspaces `@openrig/cli|daemon|ui|tui` →
  `@openrig-local/cli|daemon|ui|tui`.
- All current import specifiers, `tsconfig` paths, workspace links, lockfile entries,
  build/install/packaging scripts, test fixtures and current docs updated to the new scope.
- `rig --version` prints `openrig-local <semver>` (with the build stamp when stamped).
  `CLI_VERSION` remains the bare/stamped semver for machine consumers (for example MCP
  `serverInfo.version`).
- Root and CLI package descriptions name the local fork.
- `/UPSTREAM-BASE` records the fork policy as machine-checked keys: `fork_model`,
  `upstream_role`, `version_line_policy`, `sync_cadence`, `integration_model`; the validator and
  its tests reject a different policy.
- New `/docs/reference/fork-and-upstream.md`: provenance, differences, version rules, and the
  read-only upstream inspection/backport procedure.
- Local version line `0.1.1 → 0.1.2` for root, CLI, daemon, UI, the private TUI, the lockfile
  and `UPSTREAM-BASE.local_line`.

## User-Facing Changes

- `rig --version` now reads `openrig-local 0.1.2` instead of `0.1.2`. Scripts that expect the
  first token to be a bare semver must use `rig --version | awk '{print $2}'`, or read
  `CLI_VERSION`/`package.json`.
- `npm install -g` of this tree, and any path referring to the installed package, uses
  `$(npm root -g)/@openrig-local/cli`.
- Command names (`rig`, `openrig-tui`), `OPENRIG_HOME`, `~/.openrig`, wire fields, runtime ids
  and plugin ids are unchanged.

## Operator / Setup Notes

- **Breaking (package identity only).** Out-of-tree importers of `@openrig/*` must switch to
  `@openrig-local/*`. An existing global install is not migrated in place; reinstall from this
  tree and restart the daemon (`rig daemon stop`, `rig daemon start`).
- No database migration runs; the newest remains 114.
- No npm publish, git tag or GitHub release is made by this cut. Publishing identity remains an
  owner decision.
- The packaged-install path classifier still recognizes a pre-rename
  `…/node_modules/@openrig/cli/…` layout, so seats created by an older local install keep
  re-anchoring to the running install.

## Known Limitations

- Historical release notes and old `CHANGELOG.md` sections keep the names they were written
  with; they are not rewritten to the new scope.
- The `openrig-local` root package is private (a workspace aggregate); only the CLI is a
  publishable artifact, and this cut does not publish it.
- Upstream inventory remains a manual, on-demand activity. No automation merges or fetches into
  the read-only upstream copy.
- The daemon/UI story-graph tests assert English month names, so the full suite is run with
  `LC_ALL=en_US.UTF-8` on hosts whose default locale is not English.
