# OpenRig 0.6.8 — catalog isolation and launch safety

> Backfilled release note, written 2026-10-24 from the `0.6.8` section of
> [`CHANGELOG.md`](../../CHANGELOG.md). It adds no new test run; the release's
> original verification record is on the
> [GitHub release](https://github.com/mvschwarz/openrig/releases/tag/v0.6.8).

0.6.8 is mostly fixes, most of them from the community: one skill being edited in
the managed catalog no longer stops every seat's skills, a launch plan can never
start a seat, Slack replies stay in their thread, and a workflow that could never
finish is caught at validate.

## Before you upgrade

- Restart the daemon after upgrading the CLI. There are no migrations, and
  openrig-core stays at 0.1.8.
- The TUI footer toggle moves to `F`, and the selected Scopes view's
  mini-requirements and narrative keys move to `M` and `N`, so ordinary words type
  whole on an empty command line. `j` / `k` move the selection.
- `rig workflow validate` reports `step_cannot_finish` and refuses to instantiate
  when no allowed exit can finish a step or route onward. A spec that validated on
  0.6.7 can be refused now.
- `rig context work-install --runtime <runtime>` and
  `rig skill loadout --runtime <runtime>` report a selected skill skipped for
  uncommitted catalog content with exit 1. Applying with `--apply-skills` / `--apply`
  still reconciles the remaining clean skills.
- `rig launch --plan` refuses a daemon older than 0.5.9, which would ignore the plan
  and launch.

## Highlights

- **Skip a managed catalog skill with uncommitted or untracked content** by itself,
  with a named warning, instead of making the whole catalog unavailable for
  `rig context work-install`, `rig up`, launch and restore preflight. A seat keeps
  the copy it already has; no runtime gets uncommitted files; launch only warns.
  Uncommitted `catalog.yaml` still makes the catalog unavailable.
- **Preview a single seat's launch** with `rig launch <rig> <seat> --plan`, locally
  or over `--host`, without starting anything. Exit non-zero when the answer is not
  a plan but shows the daemon acted.
- **Reply in the Slack thread where the person replied** for an
  `--human-intent update --reply-to <row>` answer. A Slack rate limit of 10 seconds
  or less is waited out and retried once.
- **Deliver the turn boundary, restore request and read-depth audit** to a Claude
  seat that stays quiet after a managed `/compact`, instead of waiting for its next
  turn. Each stage still waits for an idle screen.

## Other changes

- The CLI and TUI build output is finished with
  `scripts/prepare-workspace-build.mjs` instead of `chmod`, `mkdir` and `cp`, so
  building from source no longer needs POSIX shell tools. Not yet run on Windows.
- A handed-off task's summary appears on one wake line of up to 120 characters.
- `rig scope audit` accepts slice folders numbered 100 and above; `rig proof add
  --file` keeps a leading UTF-8 byte-order mark.

## Limit stated at the time

There is no separate "Known limitations" block in this changelog section. The
Windows note on the build helper above is the one explicit platform caveat; the
original GitHub release carries the verification and issue list.
