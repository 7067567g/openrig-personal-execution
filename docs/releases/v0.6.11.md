# OpenRig 0.6.11 — recovery and wasted agent time

> Backfilled release note, written 2026-10-24 from the `0.6.11` section of
> [`CHANGELOG.md`](../../CHANGELOG.md). It adds no new test run; the release's
> original verification record is on the
> [GitHub release](https://github.com/mvschwarz/openrig/releases/tag/v0.6.11).

0.6.11 is a fix release about recovery and wasted agent time, much of it from the
community. A send that waits for a seat to go idle no longer holds up every other
send to that seat, a parked seat is not woken again for rows that have not changed,
restore stops for a decision instead of silently starting a seat fresh, a Codex seat
at its usage limit stays marked as limited while its screen redraws, and on Linux a
Codex seat can be restarted in place on the same conversation.

## Before you upgrade

- Restart the daemon after upgrading the CLI (`rig daemon stop`, then
  `rig daemon start`). Migration `103` adds `sessions.intentionally_stopped`,
  defaulting to 0 for every existing row. There are no migrations `100` or `102`.
- A restore now stops a seat at `awaiting-decision` and starts nothing when the
  seat was not running at the snapshot but an earlier session recorded a resume
  token. `rig up --existing` and `rig launch` no longer start it fresh.
- `rig send --wait-for-idle N` now takes the delivery lease after waiting, and N is
  a deadline from the start of the wait, including lease time.
- `rig seat launch --fresh --stop` refuses a seat with a still-live older session
  before stopping the current agent. `--plan` previews without changing anything.
- A seat stopped with `rig seat stop` is left out of its rig's state, so the rig no
  longer reads `degraded` for it; a rig whose seats were all stopped reads `stopped`.
- `rig queue create --verify` reports `outcome: "claimed"` for a claimed row whose
  wake was not confirmed, instead of `indeterminate`.
- `rig queue whoami --work-candidates` returns up to 50 held and 50 next rows and
  reports truncation with `heldTruncated` / `nextTruncated`.

## Highlights

- **Restart one Codex seat in place on Linux**:
  `rig seat restart <seat> --keep-conversation --reason "<why>"` keeps the same pane
  and conversation on whatever account its Codex home now holds. It refuses before
  stopping anything unless the seat is a Codex seat OpenRig launched, in a single
  pane, with a provable conversation and unchanged settings. `--plan` checks without
  stopping. `--verify --expect-account` reports `moved` only after a completed tool
  turn in the same conversation and a matching account status.
- **Stop re-waking a parked seat for unchanged rows** after a wake was delivered,
  until the occupant updates a row or one changes state. A failed, refused or
  unrecorded wake still repeats. Delivered means typed into the terminal, not read.
- **Keep a Codex seat at its usage limit** as `unknown` with reason `usage_limit`
  while its screen redraws, instead of reporting `running`.
- **Report the Slack receipt beside the terminal wake** from
  `rig queue create --verify`, in a `gateway` object (`posted`,
  `transport-failed`, `never-posted`, `still-pending`). Posted is not read.
- **Give a forked Claude seat its own session ID**, so strict restore and
  clear-attention can verify it as its own conversation. Forking needs Claude Code
  2.0.73 or later, which OpenRig does not check.

## Known limitations at the time

- `rig seat restart --keep-conversation` supports Linux only, and its automated
  tests are hermetic: they do not restart a real Codex seat.
- `GET /api/rigs/:id/status` can call a running rig `blocked` because of one seat
  that is not running; no seat is halted, and `rig status` and the TUI do not show
  it for a running rig.
- A Codex seat can keep reading as at its usage limit in a constructed edge case
  that has not been seen in a real session.
- The keeping-a-watch page says a timer fires once; a held-back one-shot wake can
  make it wake the owner again at each interval while the row stays set aside.
